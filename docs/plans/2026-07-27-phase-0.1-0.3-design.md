# Phase 0.1–0.3 Completion Design

## Scope

Close every Phase 0.1–0.3 roadmap item against tested repository behavior. Existing engine, HTTP, and transit surfaces remain compatible. Work adds missing configuration and CORS behavior, proves existing benchmark coverage, completes multimodal leg timing, and updates status docs. GTFS calendar/service-date filtering remains separate because `docs/PROJECT_STATUS.json` already identifies it as a later gap rather than Phase 0.3 timetable routing.

## Engine configuration

`pkg/pathcraft/engine.Config` supplies default street mode, speed in metres per second, and OSM-highway penalty multipliers. `New()` keeps current defaults. `NewWithConfig(Config)` validates explicit configuration without breaking callers. Supported modes are walk, bike, and car; zero speed selects mode default. Penalty names are normalized and factors must be finite and at least `1`, preserving an admissible distance heuristic. Derived edge costs and route durations must also remain finite and representable.

Requests with an explicit mobility profile retain that speed/access override. Requests without one use engine configuration, making public engine routing usable without importing an internal package. Engine penalties apply in either case. A* minimizes weighted edge cost while tracking unweighted distance separately, so penalties change route choice and duration without corrupting reported metres.

## HTTP CORS

CORS remains disabled unless exact origins are supplied. `NewServer`, `RunServer`, and `pathcraft server --cors-origin` accept an allowlist; CLI input is comma-separated. Configured values must be exact HTTP(S) origins; wildcard, opaque `null`, and path-bearing values are rejected. Allowed GET requests echo their exact origin and set `Vary: Origin`. Valid preflight requests support `GET` only and return `204`. Disallowed preflights return `403`; unsupported actual or requested methods return `405`. No credential header.

## Time-dependent multimodal routing

RAPTOR reconstruction records scheduled departure and arrival for each transit step plus transfer timing. Engine journey legs expose normalized clock strings and derive non-zero durations. Walk access departs at query time; transit search begins after access duration; egress begins at transit arrival. Deterministic tests prove a trip is usable before its access-adjusted departure and missed afterward.

## Validation

Use test-first red/green cycles for each behavior. Run focused package tests, LSP diagnostics, full Go tests with race detector, Go build, frontend test/lint/build, and bounded benchmark smoke runs. Fresh read-only correctness and security reviewers inspect final diff. Parent remains sole writer and resolves material findings within three rounds.
