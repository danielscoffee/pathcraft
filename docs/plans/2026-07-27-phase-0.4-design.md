# Phase 0.4 Performance and Scale Design

## Scope

Complete Phase 0.4 at PathCraft's current prototype maturity without claiming production-scale contraction hierarchies or distributed caching. Preserve every existing library, CLI, HTTP, route-shape, mode-restriction, and highway-penalty behavior.

Acceptance means five concrete capabilities:

1. directed degree-two graph contraction reduces routing search while returning every original path node;
2. graph caches are source-bound, versioned, and atomically replaced;
3. one explicit preprocessing pipeline parses OSM, builds graph and contraction index, then writes cache;
4. loaded engines support concurrent read-only routes, matching Go HTTP request concurrency;
5. reproducible allocation benchmarks and `pprof` commands cover preprocessing, serial queries, and parallel queries.

GTFS service calendars, realtime updates, horizontal scaling, distributed result caches, and production API controls remain outside Phase 0.4.

## Chosen approach

Use a conservative directed degree-two contraction index beside the base graph.

Two heavier alternatives were rejected for this phase:

- A profile-specific compressed graph would reduce memory but needs query-time endpoint injection, profile fingerprints, and fallback policy for custom profiles.
- Full contraction hierarchies would need node ordering, directed witness searches, recursive shortcut unpacking, profile-specific artifacts, and bidirectional upward queries.

The selected index gives measurable long-chain query gains while retaining the base graph as a compatibility and correctness oracle. Full contraction hierarchies become justified only if city-scale profiles show degree-two contraction insufficient.

## Graph contraction

`internal/graph` builds immutable directed chains between retained nodes. A node is contractible only when it has exactly two physical neighbors and exactly one incoming and outgoing edge for each neighbor. Self-loops, ambiguous parallel arcs, malformed references, and components with fewer than two retained nodes stay uncontracted.

Each directed chain stores:

- ordered original node IDs;
- original directed edge segments;
- total geometric distance;
- distance grouped by highway type;
- union of restricted modes.

Index also stores retained-node outgoing chains and node-to-chain positions. Query-time arc selection supports four cases without changing endpoint semantics:

- retained source to retained target: traverse full chains;
- interior source: traverse suffixes to retained endpoints;
- interior target: traverse prefixes from retained endpoints;
- source and target on same directed chain: traverse direct subchain.

A* uses contracted arcs only when valid index exists. It stores chosen subchain in predecessor state and expands original node IDs during reconstruction. Returned node list, coordinates, distance, duration, access restrictions, and penalty-aware cost therefore match base graph behavior. Graph mutation invalidates index and returns routing to base adjacency until preprocessing runs again.

Shortcut data is profile-independent in cache. At query time, each original segment receives current profile penalty and validation before costs are summed; any restricted segment blocks arc for matching mode. Profiles exposing custom highway penalties use zero heuristic because code cannot prove multiplier lower bound. This preserves base-route error semantics and optimality even for custom discounts below `1`.

## Cache and preprocessing

Graph cache becomes a small binary header followed by existing gob graph payload. Header contains:

- fixed magic bytes;
- graph schema version;
- preprocessing version;
- SHA-256 of source OSM bytes.

`ReadCacheMetadata` reads only header, allowing CLI freshness checks without decoding graph. Schema or preprocessing mismatch rejects cache and triggers current parse fallback. Content hash prevents stale cache reuse even when timestamps are preserved.

Writes use a temporary file in destination directory, encode and sync it, close it, then atomically rename it over destination. Failed writes remove only temporary file and leave prior cache intact.

`Engine.LoadOSM` becomes parse → build graph → build contraction index → publish immutable graph. `Engine.SaveGraph` persists source fingerprint and index. New `pathcraft preprocess --file ... [--output ...]` runs same pipeline explicitly for deployment preparation. Existing route, parse, journey, and server commands keep transparent cache behavior.

No general stage framework, cache eviction manager, route-result cache, or new dependency. Existing single-file graph cache is sufficient until measured route repetition or multi-dataset operation proves need.

## Parallel routing contract

Parallelism means concurrent independent queries against a fully loaded engine. Base graph, spatial index, and contraction index are read-only after publication. OSM/GTFS loading, graph mutation, nearest-index replacement, and hot reload are excluded from concurrent-use contract.

Go HTTP server already runs requests concurrently. No batch API or worker pool is added: both would duplicate scheduler behavior without current caller requirements. Race tests and `RunParallel` benchmarks prove supported query concurrency and deterministic results.

## Validation

Test-first checks must prove:

- deterministic chain/index construction;
- full original-node reconstruction for retained and interior endpoints;
- all ordered node pairs match base A* success/error, route cost, and distance;
- walking/driving restrictions, one-way representations, mixed highways, and custom penalties stay correct;
- graph mutation invalidates contraction index;
- cache round-trip preserves contraction results;
- old, truncated, stale-source, and preprocessing-version-mismatched caches are rejected or rebuilt;
- concurrent routes return deterministic independent results under race detector;
- synthetic long-chain benchmark reports contraction gain plus allocations;
- preprocessing and parallel route benchmarks emit `ns/op`, `B/op`, and `allocs/op`;
- memory profile can be inspected with standard `go tool pprof`.

Focused tests run before full Go tests, race detector, vet, build, frontend checks, LSP diagnostics, and fresh read-only correctness/security review.

## Honest limits

Phase 0.4 completion means tested scale foundations for prototype, not global production readiness. Base graph remains in memory beside contraction index. Cache format remains Go-specific and versioned rather than stable. No hot reload, distributed cache, cross-process coordination, traffic-aware weights, or full contraction hierarchy. Documentation must retain these limits and avoid unsupported latency or memory claims.
